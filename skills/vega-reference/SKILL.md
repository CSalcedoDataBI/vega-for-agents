# Vega and Vega-Lite reference

Vega and Vega-Lite are different languages with different schemas. A name valid in one is not
automatically valid in the other, so fix the language first and then the name. One hop: read the
catalogue key you need, not the whole file. All paths below are from the plugin root.

## 1. Fix the language and the major version

Read `$schema` in the spec.

- The path segment after `/schema/` names the language: `vega-lite` → Vega-Lite, `vega` → Vega.
  Do not carry a mark, channel, transform or property from one language to the other.
- Major version: v6 is the default; use v5 only when `$schema` declares v5. A version mismatch is
  a different vocabulary, not a fallback.

| Language | v6 (default) | v5 |
|---|---|---|
| Vega-Lite | `exports/vega-lite-v6.catalog.json` | `exports/vega-lite-v5.catalog.json` |
| Vega | `exports/vega-v6.catalog.json` | `exports/vega-v5.catalog.json` |

If the spec has no `$schema`, treat it as v6 and say so; ask for the version when the answer
depends on it.

## 2. Look the name up in that catalogue

The catalogue is a JSON object. These are its keys:

| What you are checking | Vega-Lite | Vega |
|---|---|---|
| Mark | `marks` (the `mark` value) | `marks` (the `marks[].type` value) |
| Encoding channel (key under `encoding`) | `channels` | No encoding channels in Vega |
| Transform | `transforms` | `transforms` |
| Scale type (`scale.type`) | `scaleTypes` | `scaleTypes` |
| Projection type (`projection.type`) | `projectionTypes` | Not enumerated (free string or signal) |
| Any property key | `properties` | `properties` |

Search the exact name under the key; do not read the whole catalogue and do not infer a name
from a nearby one. A name can be a valid property and still be invalid as a mark, channel,
transform or scale type; the key decides the role. `$schema` is always accepted.

Every catalogue has a `meta` block; in the schema catalogues, `meta.schemaVersion` names the
schema version and `meta.schemaSha256` is the SHA-256 of the schema it came from; use them to
confirm the version.

## 3. Check the adopted traps

`exports/adopted-traps.catalog.json` lists known authoring traps. Each entry has a stable `id`,
its `language`, a `symptom`, a `cause` and a `fix`. Read the entries for the language in hand before
writing a spec; the long form of each note is under `reference/drafts/`, and its table maps each id
to its note.

The trap catalogue is authored reference content, not a name vocabulary. It never replaces the
schema catalogue check in step 2: a name is valid only if it is in the schema catalogue for the
spec's language and version.

## 4. Expressions and event selectors

The JSON Schemas type these as free strings, so the schema catalogues cannot answer them.

- Expression functions: `exports/vega-v6.expressions.catalog.json`. Each entry of `functions[]`
  carries `name`, `signatures`, `documented` and `since`; the top-level `categories` groups the
  functions. Entries with `documented: false` are internal names: never write them. Cards:
  `reference/vega/expressions/README.md` and one page per category in `reference/vega/expressions/`.
- Event selectors: `exports/vega-v6.event-streams.catalog.json`. The `markTypes`, `markEventTypes`,
  `namedSources` and `specialEventTypes` keys are the vocabulary; `syntax` and `examples` show the
  grammar. Card: `reference/vega/event-streams.md`.

These two are the only expression and event-stream vocabularies in the plugin, and both are Vega
6.4.0. Function entries carry `since`, and so do versioned special event types; check it against the
spec's version before using the name. `resize` is `since: "6.4"`, for example, so a spec that
declares a v5 `$schema` cannot use it. Vega-Lite expressions compile to Vega expressions, so the
same function list applies, with the same `since` check; its `on` and `clear` selectors use the Vega
selector grammar.

## 5. If the name is not there

It does not exist for that language and role. Do not use it, and do not "fix" the catalogue:
`exports/*.catalog.json` is generated by `scripts/extract_catalog.py` and is never edited by hand.
The schema catalogues come from the official schemas; the trap catalogue comes from
`scripts/adopted_traps.py`. A missing name means a new schema version and a re-extraction,
following `CONTRIBUTING.md`. Report it with the `vega-feedback` skill or a plain issue.

## 6. Out of scope

Power BI and Deneb authoring (`pbiFormat`, templates, cross-filter) lives in a separate private
sibling. This skill is a reference, not a tutorial, and it does not render specs; the Vega engine
does.

## Example

A v5 Vega-Lite spec declares the version in `$schema`. The v5 catalogue backs `bar` under `marks`,
`x` and `y` under `channels`, and `$schema`, `data`, `values`, `mark`, `encoding`, `field` and
`type` under `properties`. The encoding type values `nominal` and `quantitative` are in the schema
but not catalogued, so they are not checked here; the objects inside `values` are data, not names.

```vega-lite
{
  "$schema": "https://vega.github.io/schema/vega-lite/v5.json",
  "data": {"values": [{"category": "A", "amount": 28}]},
  "mark": "bar",
  "encoding": {
    "x": {"field": "category", "type": "nominal"},
    "y": {"field": "amount", "type": "quantitative"}
  }
}
```
